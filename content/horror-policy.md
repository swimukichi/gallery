# ホラー企画・設計・実装の必須方針

サイトを企画・設計・実装するときは、以下を必須方針として扱う。
共通資料フォルダにも同じ内容を置く（下記「共通資料との同期」）。

保存日：2026-10-04（作者の指示をそのまま整理。解釈を足した箇所は「※」で示す）

## 企画の方向性
現状のテーマはホラー。『ソドムの市』『屋敷女』『アンチクライスト』や、Acid Bath、Black Sabbath、Slayer、Eyehategod に通じる嗜好を出発点にする。

- 広い層への適合を目標にしない。強い嗜好を持つ人に深く届く作りにする
- 好みが分かれる題材や表現を、一般受けのために丸めない

## 1. 逆転質問を必ず使う
目的を直接達成する方法を考える前に、目的の逆を問う。

> 例：「どうすれば最高に怖い物語になるか」
> →「絶対に誰も怖がらない、最も退屈で無意味な日常のルールとは何か」

- そのルールが安心を成立させている**前提**を特定する
- 前提・結果・人物の立場を反転して、異様な状況を組み立てる
- 単に残虐描写を増やすだけで終わらせない
- 物語だけでなく、**サイトの機能・画面・情報の見せ方**にも適用する

## 2. 対立仮説を必ず立てる
「絶対に正しい」「疑いようがない」と感じる前提を明示し、真っ向から反論する仮説を立てる。

> 例　前提：「ホラーのサイトは暗い画面ほど怖い」
> 　　対立仮説：「明るく事務的な画面に説明不能な記録が混じる方が、不穏さが強い」

- 双方について**成立条件と弱点**を考える
- 試作や観察で判断できる形にする。直感だけで採否を決めない

## 3. 不条理な仮説を発想の起点にする
最初から筋の通った美しい完成形を作ろうとしない。まず不条理で突拍子もない仮説を出す。

仮説から次を掘り下げる。
- 何が起きれば成立するか
- 誰の生活や判断が変わるか
- どんな矛盾や帰結が生まれるか

未完成・矛盾・未解決の案も保存する。早い段階で既存の型に収めない。

## 4. 企画案に残す項目
各案に以下を記録する。逆転案を必ず採用する必要はないが、検討は省略しない。評価は作者の意図と、狙う人の嗜好に照らして行う。

```
## 企画案：<仮題>
- 達成したいこと：
- 逆転質問と、そこから出た案：
- 当然視している前提：
- 対立仮説：
- 不条理な仮説の成立条件と帰結：
- 採用／修正／棄却を判断するための試作・観察方法：
- 状態：（未完成・矛盾・未解決でもそのまま残す）
```

## 5. 資料と創作をつなぐ
映画、メタルの楽曲、歴史、実際のニュース、作者自身のアイデアを参照する。調査メモは必ず次の 2 つに分ける。

```
## 確認できた事実
- 出典：
- 日付：
- 未確認点：
- 情報の食い違い：

## 小説への落とし込み
- 恐怖の仕組み：
- 架空の人物・舞台・葛藤への変換案：
```

- 大胆な創作上の仮説と事実確認を両立させる
- 創作上の推測を、史実やニュースの事実として扱わない
- 欧州・アメリカ・アジアの現地資料や小規模媒体も探し、複数の情報源を照合する
- **無料公開情報のみ**を使う。追加費用を発生させない
- **リサーチでサブエージェントは使わない**

## 6. 制作の流れ
1. 資料を参照してホラー小説を作る
2. その小説で扱ったテーマを解説する記事も作る
3. 週 1 回の執筆を想定。曜日は未定
4. 画像生成は、作者が開始を指示したときに行う

※ 既存の連載運用（CLAUDE.md「投稿のリズム」＝小説は毎日 1 章）との関係は未整理。この方針の「週 1 回」は新企画側の想定として別に扱い、既存の連載は止めない。

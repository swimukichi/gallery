# お披露目パック

手本：怖話工房（`horror-maker/` の ARTICLE-01.md・ARTICLE-01-ameblo.md・X-POSTS.md・CODEX-PROMPT.md、画像 `content/assets/horror-maker/`）。
いきなり「使って」と言わず、「こういうものがあったらどう思いますか？」と見せて反応と要望を集め、公開するかをその後で決める。

## 1. 対象を 1 文で決める（最初にチャットで出す）
- 「この手のものは溢れている」前提で、誰のためかを 3 案（A 主軸候補／B 使い方の一つ／C 一番尖る案）の表で出し、おすすめを明記
- 決まった軸で「冒頭の一文」「こんな人へ（3〜5 項目）」「作った理由」を、すぐ使う版・少し凝った版で出す
- 作った理由は本人の言葉で決まる。仮の文を書いたら「仮」と明記し、本人に確認を求める
- 本人の既存作品を載せるときは事実どおりに書く（そのサイトで作っていないものを「このサイトで作った」と書かない）

## 2. サイトの全体像
- 冒頭 → ナビ → こんな人へ・作った理由 → 本体 → 作品 → 今後の予定（準備中／試作中／構想中の印）→ フッター
- OGP（title・description）も同じ軸で書く

## 3. スマホで見られるようにする
- claude.ai の Artifact に限定公開のプレビューを出す（本人のスマホで開ける。他人は共有設定が要る）
- API が要る部分はページ内のダミーに差し替え、上部に「プレビュー版：生成はダミー」と出す
- 怖話工房は `node horror-maker/tools/build-preview.mjs <出力>` で作れる。同じファイルパスで出し直せば URL は変わらない
- 幅 400px で横スクロールが出ないか、Playwright（`/opt/node22/lib/node_modules/playwright`、executablePath `/opt/pw-browsers/chromium`）で確認する

## 4. スクショ
- Playwright で 390×844・deviceScaleFactor 3。要素の上下に 24px の余白を付けて撮る
- ダミーの文章は `filter: blur(4px)` でぼかし、タイトルは「（作品タイトル）」に置き換える。ダミーを本物に見せない
- 数（テーマ数など）は実物と合わせる。合わないときは表記を直す（例：「約30種類」）
- 保存：`content/assets/<slug>/shot-NN-<内容>.png`。撮ったら SendUserFile でスマホに送る

## 5. お披露目記事（note とアメブロの両方、同じ日時に予約）
- ファイル：`<作業フォルダ>/ARTICLE-NN.md`（note）、`ARTICLE-NN-ameblo.md`（アメブロ）
- 冒頭に目的・予約日時・画像の対応・「リンクは貼らない（公開前）」を書く
- note：タイトル 3 案 → あいさつ（今日は相談です／まだ公開していません）→ 何ができるか（3 ステップ＋画像）→ ほかとの違い → 独自の要素 → 自分の作品とのつながり → 聞きたいこと 3 つ → 締め（当日の連載へ誘導）→ ハッシュタグ。少し凝った版は冒頭の差し替えで出す
- アメブロ：note より短く話しかける調子。見出しは「■」。note への誘導記事ではなく単体で読める全文版。画像は見出しの直後。ハッシュタグは 8 個前後
- 予約時刻は CLAUDE.md「投稿のリズム」と `content/schedule/` を見て、図鑑・小説とぶつけない（仮定なら明記）

## 6. X の宣伝投稿（7 本・1 週間）
- ファイル：`<作業フォルダ>/X-POSTS.md`。冒頭に方針と予約表（日時・内容・画像）
- 流れ：① 予告 → ② 記事告知（固定ポスト）→ ③〜⑥ 機能・独自要素・一覧・作った理由を 1 つずつ → ⑦ 投票
- 各投稿にすぐ使う版と少し凝った版。凝った版は情景や具体例で止める
- リンクは本文に入れず、自分への返信に貼る
- 書いたら必ず `node .claude/skills/showcase/x-count.mjs <X-POSTS.md>` で 280（全角 140 字）以内を確認する

## 7. 予約の代行（Codex 用プロンプト）
- Claude はログインできないので予約・リンク貼り・固定はできない。できないことを先に伝える
- `<作業フォルダ>/CODEX-PROMPT.md` を作り、**全文をチャットにもコードブロックで貼る**（本人は GitHub の master を見るので、ブランチにしか無いファイルは見つからない）
- 中身：素材の場所（リポジトリ・ブランチ・ファイル）／原稿の扱い（``` の中だけ、画像の対応、一字も変えない）／媒体ごとの手順と予約日時／やってはいけないこと（即時公開・書き換え・既存投稿の編集・設定画面・ログイン入力）／報告内容
- 前提として「ログイン済みブラウザを操作できる Codex でないと動かない」「パスワードは渡さない」を添える
- 公開後にしかできないこと（記事リンクの返信・固定ポスト・予約できない投票）は本人の作業として別に列挙

## 8. 後始末
- 変更はセッションの作業ブランチにコミットして push
- 投稿後は d1・d7 を `/stats` で記録。返信で出た要望は「今後の予定」に反映する
